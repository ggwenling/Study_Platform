# 静态资源压缩与转换速查

用户问“这个格式怎么压”“用什么工具”“有没有网站能处理”时，先弄清资源拿来做什么、是不是关键路径、当前格式和尺寸、浏览器覆盖以及隐私等级。压缩只是候选改动，格式、尺寸候选、引用、缓存和验证要分开说。

## 先选一条处理路径

1. **生产管线或 CDN 已有转换能力**：优先复用它，避免本地副本、缓存键和响应式候选失去一致性。
2. **需要可重复、批量、可审查的改动**：选择版本锁定的本地 CLI 或构建插件，保留命令与输入/输出报告。
3. **一次性、非敏感、人工检查的资源**：可以给在线工具作为备选；先说明文件会离开用户设备（除非用户已自行确认该工具的本地处理和组织合规性）。不要上传包含用户信息、内部设计、未发布素材、授权内容或带敏感 EXIF 的文件。

推荐时别只报工具名。顺带说清适用格式、是否有损、最可能出的回归、需不需要源文件/回退，以及怎么用 Network/trace 证明它确实改善了路径。

## 按格式选方案

| 资源 | 本地/构建方案 | 适合的情况 | 关键限制与验证 |
|---|---|---|---|
| JPEG 照片 | `jpegli`、MozJPEG 或 ImageMagick；另生成 WebP/AVIF 候选 | 照片、渐变等连续色调 | 先按实际显示尺寸缩放；有损重编码只从高质量源图做，检查肤色、渐变和文字边缘。 |
| PNG（透明图、线稿） | `oxipng`/`zopflipng` 做无损压缩；`pngquant` 做有损量化；必要时生成 WebP/AVIF | 需要 alpha、图标、截图 | 无损方案主要省传输；有损量化要检查色带、透明边缘。不要为“更小”丢掉需要的 alpha。 |
| WebP / AVIF | `cwebp` / `avifenc`，或项目现有图片管线 | 已确认目标浏览器和 CDN/MIME 支持 | 避免重复有损重编码；质量数字不能跨编码器比较。AVIF 编码成本也应纳入构建/CI 预算。 |
| SVG | `svgo`，或构建期 SVG 优化插件 | 矢量图标、插画 | 默认保留 `viewBox`、可访问属性、被 CSS/JS 引用的 ID 和动画；先逐个审查优化配置。 |
| WOFF / TTF / OTF | FontTools 的 `pyftsubset`，再生成 WOFF2 | 字体子集、未使用字重或字符集很大 | 覆盖语言、动态文本、货币/标点、emoji 回退；不要重复压缩 WOFF2，也不要删除生产排版必需字形。 |
| CSS / JavaScript | 由现有 bundler 的 minifier、tree-shaking、chunk 策略和 CDN Brotli/gzip 处理 | 构建产物包含空白、旧语法、未使用代码或压缩缺失 | 不要手工二次压缩发布文件；静态压缩不等于减少解析/执行，仍要查看 trace。 |
| 视频（MP4/WebM） | `ffmpeg` 或媒体管线，按内容使用 H.264/VP9/AV1 和合适码率/分辨率 | 首屏视频、演示、背景动画 | 先测首帧、自动播放、字幕、海报和低端设备解码；不要从已经多次转码的文件继续有损压缩。 |
| 音频（MP3/AAC/WAV） | `ffmpeg`，网页语音/音乐可评估 Opus | 语音、提示音、可下载音频 | 语音和音乐的码率目标不同；检查时长、采样率、响度和浏览器支持。 |
| PDF / 下载文档 | `qpdf` 做结构优化，或在有原文时经 PDF 生产管线重导出 | 用户会下载的静态文档 | PDF 压缩可能改变字体、图片或可访问性；视觉与文本选择/搜索都要复测。 |

仓库中的 [optimize-image.mjs](../scripts/optimize-image.mjs) 适合单个 JPEG/PNG/WebP/AVIF 的副本实验。它不能代替 format-specific encoder、SVG 优化、字体子集化或音视频转码。

## 有损图片怎么试

质量参数不是标准化指标：`80` 在 JPEG、WebP 和 AVIF 中并不代表同等视觉质量。不要给用户承诺固定质量值；以代表性图片的小范围试验来选择阈值。

```text
1. 从实际会被请求的一张原图复制出实验样本。
2. 生成目标显示尺寸的候选，保留原图。
3. 对同一尺寸尝试少量质量档位，例如低 / 中 / 高；不在全目录扫一遍。
4. 在目标 DPR、浅/深色背景和实际裁切下比较视觉结果。
5. 只有通过视觉检查后，才用同条件 Network/trace 比较请求大小、LCP 请求开始/结束与渲染。
```

格式转换不自动改变网页引用。生成 WebP/AVIF 后，要明确更新 `picture`/`srcset`/框架图片组件或 CDN URL，并确认正确的 `Content-Type`、fallback、内容哈希和缓存策略。

## 可以提给用户的在线工具

这些服务的功能、免费额度、格式支持和隐私条款会变化。提示用户前优先确认目标格式与组织政策；不要把它们描述成生产批处理的唯一方案。

| 服务 | 适合提示的任务 | 使用前要说清 |
|---|---|---|
| [Squoosh](https://squoosh.app/) | 单张栅格图像的手工压缩、缩放、格式与质量 A/B 观察 | 适合作为人工试验台，不是批量生产管线；仍需按组织政策确认处理方式。 |
| [TinyPNG / Tinify](https://tinypng.com/) | JPEG、PNG、WebP、AVIF 等图片的快速在线压缩或转换 | 文件会提交给第三方服务；先排除敏感素材，并复核当前格式/额度限制和输出质量。 |
| [SVGOMG](https://jakearchibald.github.io/svgomg/) | 在应用 `svgo` 前手工调节 SVG 优化选项、查看结果 | SVG 优化可能删除 ID、`viewBox`、metadata 或动画相关内容；只将确认过的配置写入构建。 |
| [CloudConvert](https://cloudconvert.com/) | 罕见图片、音频、视频、文档格式的一次性转换 | 它会将文件上传并临时存储用于处理；只用于已获准的非敏感文件，不把它当作私有生产资产管线。 |

给用户的最小建议格式可以是：

```text
这张资源是 <格式/用途>，当前在 <旅程> 中 <是否关键>。
先用 <本地工具或现有管线> 在副本上做 <无损/有损/转格式> 实验，重点检查 <视觉或功能风险>。
如果只是手工试验且文件允许上传，可以用 <在线工具>；否则坚持本地处理。
生成后还需更新 <引用/候选/CDN>，并在相同条件下复测 <请求和指标>。
```

## 别给这种一刀切建议

- 不要对所有 PNG 推荐 AVIF、对所有 SVG 推荐 rasterize，或对所有资源建议更低质量。
- 不要在没有发布链路权限时建议用户“直接替换线上文件”。先输出副本、让用户决定引用变更。
- 不要把在线服务的安全或删除声明等同于用户组织的合规许可。
- 不要仅报告节省字节数；关键资源的发现时机、并发竞争、解码和缓存可能抵消收益。
