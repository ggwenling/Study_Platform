跨文档的相同句子是两份资料各自的来源。按正文去重会丢掉其中一个 document。本轮保持两份都进入上下文。

文档 Hit 与片段 AND 的差距、k=10 装不下 15–23 个行块、拒答子串误伤和漏检，都不是生成函数能补出来的缺失句子。证据残缺时的拒答保持原样。年龄换算那一类错误发生在公式行没有进 top10 的时候，本轮没有把它写成已定位的代码缺陷，也没有加计算器或按题号分支。

FIPS 46 当前下载字节与评测记录哈希不一致，仍是已知 FAIL。本轮没有改来源、没有把该项涂绿。

## 采纳的行为

这些性质由合成样本锁定，不依赖题号或金标原文。

1. **空白块不占来源编号。** 只含空白、文本不是字符串、或根本不是对象的条目会在编号前丢掉。留下的正文逐字节不变，顺序不变。`knowledge_only` 在打包后没有任何正文时，直接返回原来的「当前资料不足……」句子，不组装提示词、不调用模型。`with_general` 仍然可以在空证据上继续生成。
2. **同一个 chunk id 只保留第一次出现。** 后一次重复身份不再占用新的 `[S#]`。
3. **不同 id 的相同正文都保留。** 对应上面 48 组跨文档重复。
4. **提示词里的资料仍是 JSON 数据。** 规则原文没有改，仍然声明资料和历史不可执行。资料里的引号、换行和指令句留在 JSON 字符串内。资料正文里的 `[S12]` 只在展示时写成 `(S12)`，避免被引用解析器当成来源编号；存进引用的 `quote_text` 仍是原始正文。
5. **提示词 JSON 的字段仍是 `source`、`title`、`text`。** 没有加文档序号或 locator。保存的 100 条 evidence 用新 `prompt()` 得到的资料 JSON，与「按原顺序、原标题、原正文编号」逐条相同，失配 0。展示替换次数 0。因此这 100 条的提示词资料区与改前构造一致。
6. **引用编号与打包后的列表是同一套。** `[S1]` 对到打包后的第一块，而不是原始列表里的空白占位。编号越界仍是 `citation_invalid`。有证据、没有编号、且没有「资料不足」仍是 `citation_missing`。答案里既有合法编号又出现「资料不足」时，引用照常保留。这个子串例外没有收紧，也没有放宽。
7. **历史截断带标记。** 旧的 `[S#]` 仍先从历史里去掉，避免旧编号被当成这一轮的来源。超过 4000 字时，结果长度仍不超过 4000，末尾是 `…[已截断]`。未超过时，输出与原先的删除编号后切片相同。
8. **摘要上限在打包之后计算。** 仍是 40 块或 24000 字，超过则 `summary_scope_too_large`。空白块不再把条数撑过 40。块正文仍然不切碎。

问答路径没有新增「丢掉尾部块」的字符预算。保存证据最长 7769 字，默认语义块大约 800–1600 字、top 10 约 1.6 万字，都低于摘要已有的 24000 字上限。再砍尾部会少掉证据，不能提高正确性。

## 刻意保持的默认

| 候选 | 实测 | 决定 |
| --- | --- | --- |
| 按正文去重 | 48 组跨文档完全相同 | 保持两份来源 |
| 问答路径按预算丢掉低名次整块，或从块中间截断 | 100 条总长度都低于 8000 字；中间截断会把半截公式显示成完整证据 | 问答路径不截断资料正文 |
| 在提示词 JSON 里增加 document / locator 字段 | 保存答案的 `[S#]` 与 citation id 已经 100 / 100 对齐；多一个字段会改变每一条提示词 | 不增加字段。语义收益 NOT_VERIFIED |
| 改规则文案，要求模型在操作数不全时拒绝计算 | 保存包里的失败发生在公式行不在已保存 top10 中；改文案不能证明模型会遵守 | 规则字符串保持 `ed62865`。规则前缀 SHA256 `ad652c281bba9c16d9376548dc5391e19f017c4d6267c8f42c3d21017f0381b9` |
| 用子串或四则运算检查「引用是否在语义上支持结论」 | 合法编号不等于忠实；正确的计算结果可以不在原文里出现 | 不加解释器。语义忠实 NOT_VERIFIED |
| 为了评测子串「资料不足」而改变拒答或引用发布 | 该子串会把已写出主结论的答案标成拒答，也会漏掉没有这四个字的拒绝 | 产品判定保持原样。这是评测标签问题 |

保存的 100 条用新打包函数重放：丢掉 0 块，重编号 0，展示替换 0，资料 JSON 与身份构造失配 0。用**旧答案原文**再跑 `cited_chunks`，citation id 失配 0。这只说明编号没有被这轮改动挪动，不是新模型回答，也不能当成语义提升。

费用：0 次付费调用。CPU 开销是上面的微秒级本地计算。没有新的嵌入 token，也没有新的聊天 token。

## 未知与风险

- 真实语义、引用是否支持结论、计算是否正确：NOT_VERIFIED。
- 资料里真的出现 `[S#]` 时，模型看到的是括号形式。保存的 1000 块里出现次数是 0。模型会不会因此少引用或多拒答，NOT_VERIFIED。
- 历史超过 4000 字时，末尾多了截断标记，正文比原先少 6 个字符。多轮回答是否变化，NOT_VERIFIED。保存包没有多轮历史。
- 若同一 chunk id 带着两段不同正文出现，打包保留第一段。保存包里这种行数是 0。
- 评测服务自己判断「evidence 为空就不要调用模型」。它仍看原始列表。全是空白块时，产品对话会本地拒答，评测路径仍会去调用 `prompt()`。两边的编号在 `prompt()` 和 `cited_chunks()` 内部是一致的，因为两个函数都会打包。
- 空白块若在检索截断前就占满 top k，生成阶段只能丢掉它，不能把下一块补进来。那是检索侧的名额，不是这次能在生成函数里补回的。

## 给父协调者的接口说明

- 评测若要和产品使用同一套「空白则不调用模型」，应在调用前使用 `pack_evidence`，或直接使用 `prepare_generation`。本轮没有改评测文件。
- 检索在 top k 截断前丢掉空白块，才能把名额还给下一条证据。生成侧现在只保证空白块不会变成 `[S#]`。
- 不要为了抬 AND 把跨文档的相同句子并成一条。生成侧已用测试钉住「不同 id 的相同正文都保留」。
- k=10 在结构上盖不住需要 15–23 块的题。生成侧不会把缺失的行补出来，也没有把拒答改成硬答。若以后批准新的可保留测试索引，检索实验仍是只改 `RETRIEVAL_TOP_K`，并且不要为了对比再嵌一次已经删掉的库。
- 「资料不足」子串的误伤和漏检留给评测报告。产品发布引用的条件没有跟着改。
- 付费复读方案（未执行，也未获本轮预算）：只拿已经保存的 evidence，温度 0，复读那些证据已经齐的题，用来看补充句里的拒答字样。不重新嵌入，不重新检索，不覆盖旧答案。没有新的预算批准之前不调用。旧的战役账本不作为本轮授权。

## 后续
