## 一、定位与边界

面向大众个人用户的多功能 RAG 工具：用户将自己的资料组织到多个独立、私有的知识库，围绕选定资料提问、查看依据和提炼内容。产品先做好可信、可理解的资料问答闭环，再在同一底座上扩展学习能力。

核心价值是让用户从「存放资料」走到「找到依据并使用资料」。用户无需理解检索、索引或框架细节，也能知道回答依据了哪个知识库及哪些资料；资料不足时能明确看到这一限制。

### 非目标

- 不以考研、某一考试或学习平台作为产品主线；不要求全国考试规划或官方科目目录。
- 首版不做组织协作、企业知识门户、工作流画布、插件平台或通用 Agent 平台。
- 不把模型通用知识说成知识库内容；主动开启通用知识补充也不等于开启自动联网搜索。
- 不把 OCR 等同于图表语义理解或可靠判题；不承诺未经实测的准确率、性能或成本。
- 学习能力不是首版 RAG 闭环的前置条件；首版也不以分块编辑、检索测试等高级工具作为交付门槛。

## 三、用户价值与核心流程

### 多个独立知识库

用户按个人需要创建多个知识库，各自管理资料和索引，知识库之间保持独立和私有。权限与检索范围由服务端校验，不能只依赖页面选择。用户从聊天页即可选择或创建首个库并上传资料，无需先进入管理台；不预设自动创建默认库。

### 导入与理解资料

用户上传资料后可看到解析和索引状态、成功或失败结果，并预览可用内容。图片首发覆盖文字 OCR、识别结果预览与原图回看；扫描 PDF 同样支持文字识别及原文件回看。图表语义理解属于后续能力，不能把识别出的文字当作完整图表含义。

### 在聊天中使用资料

首页直接聊天。用户在同一会话的每一轮都可以选择知识库，会话不绑定唯一知识库。每轮记录并展示所选库及资料依据，支持从回答回看引用资料。

例如：上一轮选择 A，下一轮改选 B。A 的历史消息仍可查看，但 A 的资料与历史回答不得自动成为 B 轮的事实依据；B 轮的回答依据以本轮选定库内可用资料为准。跨轮对话可以保持可读性，但不能用历史内容绕过本轮知识范围。

默认依据选定知识库回答；资料不足时明确提示。用户主动开启模型通用知识补充后，可补充回答，并清楚标明知识库资料与模型通用知识的来源类型；此选项不自动开启联网搜索。模型通用知识不伪装成资料引用。

两种模式均先要求选定一个当前可访问的有效库。空库可以主动开启通用补充，并标明无库内依据；没有库或库失权时，先在聊天页创建或重新选择，不能用补充开关绕过范围与权限校验。

### 提炼与回访

用户可以基于选定资料请求摘要和要点提炼，并查看相应资料依据；会话历史应保留每轮的知识库选择与来源信息，便于后续回访。来源不可用时应如实提示，不能制造仍可访问的假象。

### 设备与入口

电脑和手机 Web 均支持问答、切换知识库及上传图片；复杂资料与知识库管理优先适配电脑。无知识库时，聊天页引导创建或选择首个库并上传资料，用户无需自行猜测下一步。

## 四、阶段路线与验收

阶段顺序表达产品优先级，不表示已经排期或实现。每项验收均需在真实可运行环境中验证；模型相关结果须区分测试样例、模型配置与实际效果。

### P0：通用 RAG 闭环先行

范围：创建和选择知识库、上传资料、解析与索引状态、资料预览、带出处问答、摘要提炼和会话历史；图片及扫描 PDF 支持文字 OCR、识别结果预览与原图或原文件回看。电脑和手机 Web 支持核心操作。

完成标准：

1. 新用户在聊天页能创建或选择首个知识库并上传资料，看到处理状态；成功后可预览，失败时可识别失败状态。
2. 同一用户创建至少两个独立知识库并分别导入资料，问答仅检索当前轮选定且有权访问的库；另一用户不能访问其私有资料。
3. 同一会话先问 A 再切 B，历史仍可见；B 轮不把 A 资料或历史回答自动作为事实依据，记录中能辨认每轮所选库。
4. 知识库问答和摘要能展示对应资料依据并回看；资料不足时明确提示，而不是虚构出处。
5. 默认不使用模型通用知识补充；用户开启后能区分补充内容与资料依据，且不会因此自动联网搜索。
6. 图片和扫描 PDF 能展示 OCR 结果与原图或原文件；识别不完整时结果可被用户发现，不能宣称理解图表。
7. 电脑及手机 Web 可完成问答、选库、图片上传；会话重访后仍能查看各轮选择和可用来源。

验收应覆盖正常、无库、资料不足、解析失败、无权限及切库等场景；质量结论以实际测试结果为准。

### 下一阶段：独立学习入口

左侧设置独立「学习」入口，共用知识库、资料处理、检索与引用底座。以题目分发、图片作答和判断对错组成学习闭环；用户可手动判对、判错或更正结果。展示对错及必要依据，不引入评分、满分或得分。

完成标准：

1. 用户可从学习入口获得题目并以图片提交作答，看到判断结果及必要依据。
2. 用户能手动判对、判错或更正，回看时可辨认最终结果。
3. 识别不清或无法判断时有明确处理流程，不能默默给出确定结论；具体交互在学习专题确定后验收。
4. 学习使用用户有权访问的资料，并沿用来源和知识范围边界。

待学习专题确认：题目来自抽取原题还是 AI 生成、参考答案的来源和管理、识别不清或无法判断的具体流程、人工结果覆盖规则及细节。计划、倒计时和科目目录不作为该阶段核心。

### 后续增强：质量与多模态能力

结合真实使用和评测，逐步考虑分块查看、编辑或禁用、检索测试、检索配置和原文定位等高级质量工具；图表语义理解也在后续单独评估。这些增强不强塞到学习阶段之前，也不默认一次性做成平台。

完成标准：每个被选中的增强项先定义具体用户问题、可观察结果和验证样例，再以实际效果与边界验收；尚未选中或未验证的能力不作为当前承诺。

## 五、工程复用与架构影响

### 框架边界

LangChain 可在需要时作为模型、提示词、结构化输出等内部组件；简单导入、检索和问答使用清晰的普通流程即可。只有遇到确需多步状态、分支和恢复的场景，才评估 LangGraph 与 checkpointer。用户不需要选择或理解框架，本产品也不因此建设通用工作流平台。

业务数据、消息、引用及用户操作以业务存储为权威记录；checkpoint 是可恢复的运行状态，不能替代业务事实。现有 `study` 业务 schema 与由独立 setup 管理的 `study_graph` 内部表需保持边界，不让业务迁移接管框架内部表。

### 现有设计与缺口

现有数据库设计的 37 张业务表和 checkpointer 相关基础可作为复用候选，并不意味着新产品能力已经完成。旧设计以课程和教学为中心：资料容器强绑定 course、会话含 `course_id`、学习结果含评分字段；这些结构不能直接当作新产品契约。应先核对实际实现、数据与迁移影响，再制定知识库及逐轮范围的适配方案。

需要重新明确的契约包括：

- 知识库、资料及索引状态的所有权、隔离、预览和引用回看。
- 每轮请求及历史记录中的知识库范围、资料依据和来源类型；切库时历史上下文如何防止污染当前证据。
- 资料不足、主动开启通用知识补充、解析失败及来源不可用的响应语义。
- 图片与扫描 PDF 的上传、OCR 结果和原文件访问，以及手机端所需交互。
- 学习阶段的图片作答、判断结果和用户修正；不沿用评分字段作为产品要求。

旧架构及 API 文档中的课程路径、Tutor 流程与评分语义是遗留设计，不应被当作已对齐的新接口。接口名称、数据迁移和兼容策略应在实现设计中确定，不能仅靠重命名字段完成迁移。
