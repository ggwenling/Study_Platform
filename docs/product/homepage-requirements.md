# 考研初试学习工作台：首页功能需求

版本：V1.0｜日期：2026-11-14｜状态：产品方向已确认，供设计、开发与验收使用。

本次交付为需求文档。本文的 P0 表示工作台首发必须具备的能力，不表示这些业务功能已实现。

## 1. 产品定位与目标

面向使用自有资料备考硕士研究生初试的考生，提供登录后的个人学习工作台。用户每天进入后，首先知道今天学什么，并能开始或继续一项明确的学习任务。

- 首版围绕一个当前报考目标、多门备考科目组织学习。
- 报考信息明确时，按招生年度、院校、专业／方向匹配科目；尚未确定院校时，也能自选科目开始学习。
- 以资料学习、AI 测验、错题复习、记忆卡复习形成学习闭环；问答和笔记作为学习辅助入口。
- 电脑端优先，手机首版以查看任务、目标、进度和处理状态为主。
- AI 起草学习计划，由用户编辑确认；首页执行已确认计划，不以模型输出直接替用户改变安排。

**核心成功行为**：用户从首页进入一项当前可执行的学习任务，并产生可核验的完成记录。

## 2. 已确认范围与优先级

| 范围 | P0：首发要求 | 后续／本期边界 |
| --- | --- | --- |
| 用户与页面 | 考研初试考生、登录后个人工作台 | 公开营销首页、考公考证、复试不在本期 |
| 目标管理 | 一个当前目标，多科目；报考信息可待完善 | 多目标并行与择校比较后续另立需求 |
| 科目匹配 | 已收录且核验的目录自动匹配；未覆盖可手填 | 不承诺首版全国院校专业完整覆盖 |
| 学习计划 | 基于已确认科目及可用资料起草，用户确认后生效 | 持续自动调度、自动覆盖旧计划后续评估 |
| 学习任务 | 资料、AI 测验、错题、记忆卡四类均可执行 | 各学习子页面的完整交互另有需求；首页闭环依赖其上线 |
| 资料 | 文本型 PDF、DOCX、纯文本；处理状态及恢复入口 | 扫描 PDF、照片 OCR 为 P1 |
| 首页信息 | 目标、日期、主行动、今日任务、到期复习、各科进度、资料状态 | 复杂分析报告、学习时长趋势、社交排行榜为后续范围 |
| 设备 | 电脑端完整首页流程；手机端可查看和浏览状态详情 | 手机上传、编辑计划、完整学习流程不作为首版验收门槛；小程序与原生 App 另立需求 |

本文将计划、错题与首页基础汇总提升为工作台 P0 依赖。原架构/API 草案中相关能力的优先级较后，需要重新拆分排期；不能仅按原有优先级交付后便宣称本工作台可用。

## 3. 参考项目借鉴与国内场景适配

参考 [manav-2812/synapse](https://github.com/manav-2812/synapse)，调查固定到提交 `5b703caca014cbfe71c4a09238e68661e9526a1f`。结论来自源码阅读，未运行其线上产品。

| 参考事实 | 本项目处理 |
| --- | --- |
| dashboard 受登录保护，默认入口转向工作台。[S1] | 同样定义登录后工作台，产品介绍与注册页不混入本需求 |
| 首页以推荐行动、学习状态、笔记／资料／测验等入口组织内容。[S2]、[S3] | 保留“下一步行动”，围绕当前考研目标和今日任务调整信息层级 |
| Focus Pulse 推荐由条件规则实现。[S2] | 首页主行动采用可解释规则；AI 用于计划草稿，不把规则排序包装为 AI 决策 |
| 有多种学习统计及移动端布局规则。[S3]、[S4] | 首版保留任务完成、到期复习等可验证信息；手机按已确认的查看范围验收 |

国内适配落实为：简体中文界面、考研报考信息与科目代码、招生年度和来源核验、中文资料长标题、错题与记忆卡分开计数，以及 `Asia/Shanghai` 本地日期。以上是本项目产品决策，不是未经调研的市场偏好结论。

2027 年研招规定说明初试一般为四个单元，并存在三、两个单元的设置；科目由相关规定和招生单位确定。[S5] 研招网目录支持按专业、招生单位查询，并说明数据由招生单位上报。[S6] 因此，本产品按对应年度目录匹配，不使用“学硕／专硕 → 固定四科”的硬编码规则。规则与目录需要随招生年度复核。

## 4. 首页信息结构

### 4.1 电脑端结构

```text
顶栏：产品标识                         个人账号
左侧导航：工作台／科目与资料／AI 测验／错题本／记忆卡／学习计划

主区
  当前目标：招生年度、院校、专业／方向、科目确认状态、日期信息
  主行动：继续学习／开始下一任务／完成首次设置
  今日任务：科目、任务类型、状态、预计耗时、开始入口
  待复习：到期错题与记忆卡，分别显示数量

辅助区
  各科概览：当前计划执行情况、待补资料
  资料处理：上传／解析／就绪／失败／暂不支持的扫描件
  计划提醒：草稿待确认、逾期未处理、目标变更待确认
```

主行动与今日任务优先于统计卡片。辅助区可采用右栏或下方区域，不预设品牌色、字体与最终像素布局。问答、笔记可从资料与任务上下文进入，避免首页出现多个同等权重的主按钮。

### 4.2 手机端范围

- 按“目标 → 主行动状态 → 今日任务 → 待复习 → 科目与资料状态”纵向排列。
- 可查看任务详情、目录来源、进度及错误说明；需要电脑操作的入口明确提示“请在电脑端继续”。
- 不以整页缩放或横向滚动展示桌面布局。长院校、专业和文件名可换行或展开。
- 首页查询、状态刷新与错误恢复在手机可用；复杂表格、上传和编辑流程不作为手机 P0。

## 5. 核心用户路径

### 5.1 首次进入

1. 填写招生年度及已知报考信息；院校、专业未定时可跳过相应字段，目标显示“待完善”。
2. 获取目录匹配结果或自选科目，完成科目确认。
3. 将至少一份支持格式的资料关联到相应科目，等待解析和索引就绪。
4. 填写每日可用时长、计划起止日期，选择已就绪资料，生成 AI 计划草稿。
5. 检查各科覆盖、任务安排与预计耗时，编辑并确认计划。
6. 首页展示今日任务，用户开始学习。

用户可分次完成设置，刷新和重新登录不会丢失已成功保存的步骤。目标信息待完善不阻断已确认科目的学习；科目未确认、无可用资料时，不生成看似可执行的资料学习任务。

### 5.2 日常回访

查看当前目标与任务 → 继续有效的未完成任务或开始下一项 → 完成后返回首页 → 更新任务与复习状态。用户也可自行选择其他任务，不必接受主行动推荐。

### 5.3 目标或科目调整

展示新旧配置与受影响的科目、待办和资料关联 → 用户确认或取消 → 必要时重新起草并确认计划。确认前取消不改变原配置；确认不删除历史学习记录或原始资料。目录更新不静默覆盖用户已确认的科目。

若变更影响科目或任务范围，确认新配置时旧计划即暂停执行并保留只读历史，首页按新配置引导准备计划。新草稿失败或取消不自动恢复旧目标与旧安排；用户可再次编辑目标或重试起草。该流程与同一目标下重新生成计划不同，后者在新草稿确认前保留原活动计划执行。

## 6. 功能需求

### F01 当前目标与科目匹配

**展示字段**：招生年度、目标院校、院系（如需）、学位类别、专业名称／代码、研究方向及学习方式（如需）、目标完善状态、科目列表与确认状态。

- 自动匹配必须使用同一招生年度、对应院校专业目录的核验记录。目录记录应能追溯到来源链接、版本或核验时间。
- 专业／方向不足以唯一定位时，列出候选，要求补选能消除歧义的院系、方向、学习方式等信息；不默认采用第一条。
- 支持两、三、四单元等不同组合；若目录明确存在同一单元的可选科目，由用户择一，不能把全部备选都作为必修科目加入。
- 自动结果展示科目代码与名称。用户确认后，才作为当前学习范围；“目录已核验”与“用户已确认”是两个不同状态。
- 未收录、当年未公布、来源冲突或查询失败均不得由 LLM 补出精确科目。提供原始来源查看、重试及手动设置入口。
- 手动设置至少填写科目名称，已知代码可填写；显示“用户设置”，不标记为官方核验结果。
- 未确定院校的用户可先确认自选科目。后续补全报考信息时，展示与新目录的差异，再由用户决定保留或调整。
- 影响科目、资料范围或任务安排的变更，按 5.3 的确认时点暂停旧安排并准备新草稿；仅补充且不影响现有科目和任务的目标信息，不必暂停计划。历史完成记录保留，不得仅按显示名称或科目代码自动合并旧资料。

### F02 日期与倒计时

- 分别保存和展示招生年度、官方初试日期、用户自定备考目标日、个人计划起止日期，不能将 `study_plans.end_date` 直接视为考试日期。
- 官方日期以初试开始日计算倒计时，可同时展示考试日期区间。已核验时显示“距初试 X 天”及来源；仅有自定目标日时显示“距自定目标日 X 天”；均无日期时显示目标年度及“初试日期待确认”。
- 不以招生年度直接推算考试自然年或固定日期。官方日期更正后提示用户查看对计划的影响，不自动重排任务。
- 天数按 `Asia/Shanghai` 的本地日历日期差计算。官方日期当天显示“今日初试”；过期显示“初试日期已过”，引导检查目标，不显示负数倒计时或自动切换到复试。

### F03 AI 计划草稿与确认

**输入**：已确认科目、当前报考目标（可待完善）、可用资料范围、每日可用分钟数、计划起止日期；已确认考试日期作为时间约束。

- 每日时长必须为正，计划结束不得早于开始；若计划越过已确认的初试日期，先提示修正。
- 草稿只引用用户有权访问且已就绪的资料。部分科目缺资料时，明确显示“当前覆盖 X／Y 科目”，允许用户接受部分覆盖；缺资料科目显示补充入口。
- 四类任务是支持的能力，不要求每天都有四类。无错题或无到期卡片时，不凭空生成复习对象；已有或可依据资料生成的测验、记忆卡须有明确准备步骤。
- 草稿可调整任务日期、顺序、内容范围，删除不需要的任务。确认前的草稿不计入今日完成率，不产生正式待办。
- 任务必须有科目、类型、目标资源或可追溯的生成条件、计划日期；预计耗时若提供，标为“预计”。每日预计任务耗时不得超过用户设置的可用时长。
- 生成中展示状态；重复点击不产生多个正式计划。失败可重试，保留已保存配置。同目标、同科目配置下重新生成时，原有有效活动计划继续可执行；目标／科目变更时按 5.3 处理。
- 用户确认时固定计划版本与资料范围。确认后才成为当前活动安排；同配置重新生成的新草稿在确认前不替换原活动计划。
- 逾期任务提示处理，不自动移到今天。重新安排需用户确认，并重新计算受影响日期的任务数量；只调整未完成任务，已发生的完成事件与历史版本保持不变。

### F04 主行动与继续学习

每个首页状态最多突出一个主行动；按以下顺序选择，并说明任务名称、科目和预计耗时（如有）：

1. 当前配置尚无可执行的活动计划、仍需完成首次准备：引导缺失步骤，如“确认科目”“导入资料”“生成计划”“确认计划”。
2. 已有活动计划且存在当前目标内、仍可访问的未完成学习会话：显示“继续学习”。
3. 无可恢复会话：显示“开始下一任务”，按用户已确认的今日任务顺序选择可执行项。
4. 今日没有可执行待办但存在到期复习：显示“开始到期复习”。
5. 仅有逾期待处理：显示“调整逾期任务”；确无待办与复习时，提供“查看学习计划”。

- 只有保存了实际恢复位置或会话状态，才能显示“继续”；仅有最近访问链接时使用“打开”或“查看”。
- 已有同配置的有效活动计划时，新草稿生成中、失败或待确认只作为辅助提醒，主行动继续按第 2–5 项服务原计划，不能被“确认新计划”遮盖。
- 已完成、已删除、失去权限或属于旧目标的任务不作为继续对象。点击前发现目标失效时，保留其他可用首页内容并引导重新选择。
- 不把打开资料、点击按钮、进入聊天窗口视为任务完成。

### F05 今日任务

每项展示：科目、任务标题、四类之一、计划日期、预计耗时、执行状态及单一操作入口。今日任务只来自用户已确认的活动计划；逾期、跳过与不可用需要单独识别。

| 类型 | 执行动作与完成口径 |
| --- | --- |
| 资料学习 | 定位指定资料／章节；用户明确标记完成后记录，阅读页打开不自动完成 |
| AI 测验 | 打开已生成测验；需要准备时先异步生成。成功提交作答后计完成；评分中、评分失败状态另行显示，不把提交等同掌握 |
| 错题复习 | 针对已存在、当前可复习的错题集合开始会话；本次目标集合的复习结果成功提交后完成 |
| 记忆卡复习 | 针对明确的卡片集合开始会话；达到本次会话目标并提交复习记录后完成 |

- 学习内容未生成但具备资料条件时，入口显示“生成测验／生成记忆卡”，成功后才允许开始；生成失败不标任务完成。
- 不可用的目标显示原因和恢复入口，不能跳到空页面或静默删除任务。更换目标资源或跳过任务由用户确认。
- 从业务模块返回时刷新相应任务。重复提交、刷新、网络重试不重复计完成；不能仅凭前端乐观状态永久记账。

### F06 待复习

- 错题与记忆卡按当前目标的有效科目范围聚合；展示“待复习 X 题”和“待复习 Y 张”，单位分别呈现。
- 到期以服务端复习安排与当前时刻判断；剔除已移除、无权限、已停用或不满足复习条件的内容。
- 区分从今日计划进入的复习与额外自主复习：前者关联并更新相应任务；后者更新复习队列，不凭空增加今日计划完成数。
- 复习会话的目标集合在开始时确定，新增到期内容进入后续会话，避免目标不断增长。
- 没有错题时提示“完成测验后可在这里复习错题”；没有卡片时提供从可用资料生成记忆卡的入口。

### F07 各科概览与进度

- 每科展示已确认科目名称、今日已完成／已安排任务数，以及资料是否齐备；可进入该科目资料与任务。
- 总览显示当前计划执行进度，明确统计范围；缺资料科目显示“待补资料”，不以零掌握度代替。
- 页面上的完成率表示任务执行情况，不代表考纲覆盖率、真实知识掌握度或预估考试分数。
- 首版不使用无可靠采集依据的学习分钟数、连续天数或排名作为核心激励。

### F08 资料导入与处理状态

- 上传前选择已确认科目。支持文本型 PDF、DOCX、纯文本；展示服务端约定的格式、数量与大小限制，客户端与服务端校验一致。
- 状态区分上传中、处理中、可学习、失败、需 OCR。上传进度不等同解析与索引进度；不可伪造精确解析百分比。
- 只有解析与索引均可用的资料才纳入本次 AI 计划的可用范围。后台处理中仍可查看首页、使用其他就绪资料。
- 扫描件、仅图片内容或无法提取有效文本的文件，提示“暂不支持该资料的文字识别”，提供更换文件入口；P0 不启动 OCR 或无限停留在处理中。
- 支持格式不等于承诺复杂版式、公式和图表提取完全准确。提供原文及解析预览入口；异常内容需提示确认，不能作为已核验答案使用。
- 失败可重试或更换文件；成功与失败状态需可在刷新后恢复。已保存资料不因计划生成失败而丢失。

## 7. 状态、日期与指标口径

### 7.1 关键状态

| 情况 | 首页行为 |
| --- | --- |
| 无目标、无科目 | 显示设置引导；允许院校待定后自选科目，不堆叠空统计卡 |
| 目标待完善但科目已确认 | 显示待完善标记，允许资料与计划流程继续 |
| 目录缺失／冲突／查询失败 | 如实区分原因；保留手动设置或重试入口，不展示猜测结果 |
| 无就绪资料 | 引导上传或等待处理；显示已有任务状态，不伪造 AI 计划 |
| 计划生成中／失败／草稿待确认 | 同配置下旧活动计划继续可执行，草稿为辅助提醒；目标变更后的旧计划仅保留只读历史 |
| 今天未安排任务 | 显示“今日未安排任务”，仍可查看到期复习和调整计划 |
| 今日任务全部完成 | 显示实际完成数；额外复习入口可用，不自动增加任务制造未完成状态 |
| 模块加载失败 | 该模块显示未知／加载失败及重试，其他模块可用；失败数量不显示为 0 |
| 会话过期或账号切换 | 转入认证流程，清理前一账号的个人缓存，禁止短暂展示其他人的数据 |
| 资料／任务失效 | 解释不可用并提供调整入口，保留其他内容和历史完成记录 |

### 7.2 计数口径

- **今日任务数 N**：当前活动计划中本地日期为今天、尚未跳过或移出的不同任务数。不可用但未处理的任务仍计入，并标明需处理。
- **今日完成数 D**：上述任务中已有服务端成功完成记录的不同任务数。完成率为 `D / N`；`N = 0` 显示“未安排”，不显示 100%。
- **跳过与改期**：不计为完成；用户确认后同步调整相应日期分母，并单独显示本日跳过数量，避免隐形修改。
- **计划执行进度**：当前活动计划的完成任务数／未跳过的计划任务数，注明计划版本；资源不可用但未处理的任务仍在分母。科目卡使用相同口径的本科目子集；分母为 0 时显示无有效任务，不显示 100%。
- **到期复习数**：当前用户、当前目标下可访问且达到复习时间的对象数，错题与记忆卡分别计数；不与任务条数相加。
- **预计耗时**：任务安排的估计值，不当作已学习时长；未知显示未估计。
- **时间处理**：时间点按后端约定保存，首页日期与“今天”统一按 `Asia/Shanghai` 划分；显示数据更新时间。

## 8. 文案与可用性要求

- 使用“目标院校”“专业／方向”“科目代码”“今日任务”“错题”“记忆卡”等中文术语。
- 科目、题目来源与生成内容区分：AI 生成练习标为 AI 练习，不标为官方真题；用户手动科目不标为官方核验。
- 原文、目录来源和引用入口可打开；资料失效时按权限返回不可用，不回显已失权原文。
- 所有主操作有中文名称，支持键盘操作和可见焦点；状态不只依赖颜色；长文本和错误信息可读。
- 计划生成、资料处理等等待过程可离开后返回；按钮重复点击不得形成重复正式任务。
- 所有 P0 入口必须有真实目标页面、必要数据与失败恢复路径。设计演示中的模拟数据应明确标注，不混作用户学习记录。

### 9.2 首页契约的最小信息

下列为待实现的业务契约要求，不是现有可调用 API，也不预设必须拆成多少个接口：

- **目标与匹配**：目标标识、招生年度、目录识别字段、匹配候选、考试单元及可选科目、来源／版本／核验状态、用户选择与确认状态、日期类型和来源。
- **计划**：草稿／活动版本、覆盖科目与资料范围、每日时长及日期区间、生成状态、确认结果、目标变更影响。
- **任务**：目标／科目／计划版本关联、四类业务类型、目标资源或准备条件、计划日期、执行与完成状态、预计耗时、不可用原因和可恢复位置。
- **首页汇总**：服务端口径的今日计数、科目子集、到期复习分项、资料处理状态、更新时间及各模块可用状态。
- **操作结果**：成功确认、完成、跳过、改期、重试等操作返回持久化结果，前端据此刷新相关模块；身份与资源可见性由服务端校验。

招生目录采集／维护后台、具体表结构与接口路径由后续技术任务设计；已核验覆盖清单、版本和更新时间是匹配能力上线的前置条件。官方页面可查询不等于存在已接入的开放 API，不承诺自动抓取、绕过登录或全国覆盖。

以下用例验证真实业务状态；院校目录示例使用已核验测试记录或明确标注的测试数据，不把虚构匹配当真实招生信息。

| 编号 | 场景 | 通过标准 |

| A01 | 首次登录，没有目标资料 | 展示下一步引导；可暂不确定院校并自选科目，不显示虚假进度 |
| A02 | 完整报考条件命中核验目录 | 展示对应年度来源、科目代码与名称，用户确认后建立学习范围 |
| A03 | 两、三、四单元目录及可选科目 | 正确呈现不同结构；有选项时须完成选择，不固定四科或全选备选 |
| A04 | 同专业存在多个目录候选 | 要求补选区分字段；未明确前不默认采用第一条 |
| A05 | 目标年度未公布或未收录 | 不套用其他年度科目；可手填并显示用户设置标记 |
| A06 | 来源冲突或目录服务失败 | 显示具体状态及来源／重试入口；不由 AI 猜科目，其他学习功能仍可用 |
| A07 | 先手动学习，后补全院校 | 显示差异与影响；取消无变更，确认不丢失资料及历史完成记录 |
| A08 | 官方日期、用户自定日期、无日期 | 标签和来源分别正确；不把计划结束日冒充考试日期 |
| A09 | 北京时间零点、日期当天与过期 | 今日分组和日历差正确，无负数倒计时或自动进入复试 |
| A10 | 文本 PDF／DOCX／纯文本及扫描件 | 前三类走有效处理链路；扫描件明确提示 OCR 未支持，不永久处理中 |
| A11 | 部分科目缺资料，其他资料已就绪 | 可对可用范围生成草稿，显示覆盖比例与缺资料科目，不假装全部覆盖 |
| A12 | 无可用资料、未确认科目或非法日期／时长 | 提示完成必要条件，不生成不可执行的正式任务 |
| A13 | AI 草稿生成失败或重复点击 | 保留配置与原活动计划，可恢复重试，不产生重复活动计划 |
| A14 | 编辑、确认或重新生成计划 | 草稿不计正式待办；确认后才切换版本，结果跨刷新保持 |
| A15 | 存在有效／失效恢复位置 | 只对有效未完成会话显示继续；失效后可选择其他任务 |
| A16 | 四类任务各完成一次 | 按 F05 的事件口径记录；打开页面不算完成，重试提交不重复计数 |
| A17 | 测验已提交但评分中或失败 | 提交任务完成状态与评分状态分开，未把提交当作掌握或官方成绩 |
| A18 | 逾期、跳过和改期 | 无自动移期；用户确认后更新日期与分母，跳过不计完成 |
| A19 | 计划外复习、新增到期对象、空复习队列 | 队列计数正确；不虚增计划完成数，本次会话目标不无限增长 |
| A20 | 今日无任务、全部完成、含不可用任务 | 三种状态有区分；0 个任务不显示 100%，不可用任务有处理入口 |
| A21 | 一个模块失败、会话过期或切换账号 | 局部错误不伪装为 0；身份变更不残留前一用户个人数据 |
| A22 | 资料软删除或资源权限失效 | 不展示失权原文；未完成计划任务仍计入 N，D 不变，直至用户确认跳过或改期；不可用复习对象移出到期队列，其他内容保留 |
| A23 | 手机、键盘与长中文名称 | 手机核心信息可读可查看，电脑操作提示明确；键盘可达且无整页横向溢出 |
| A24 | 所有首页入口与计数 | 无占位死链，路由与资源一致；任务、题数、卡片张数不混算 |
| A25 | 同配置重新生成草稿，生成中／失败／取消／待确认 | 原有效活动计划继续可执行，主行动不被草稿遮盖；仅确认新草稿后切换 |
| A26 | 目标变更确认前取消，或确认后新草稿失败／取消 | 确认前取消保留原配置与计划；确认后旧计划只读，新配置不自动回退，资料与历史完成记录不丢失 |

## 11. 上线衡量与实施顺序

**可核验的产品指标**：首日学习激活率（首次进入首页的新用户中，当日本地日期内成功完成首项任务的人数占比）、首页学习启动率（首页当日访客中，从首页入口成功启动学习会话的人数占比）、今日任务完成率、计划确认率（已保存草稿中被确认的比例）、有效恢复成功率（继续学习请求中成功恢复到对应会话的比例）。统一用户、日期与计划版本去重，排除演示及失败操作；曝光与事件采集属于待建设能力。

指标首版用于建立基线，不在没有真实数据时声称效果提升或设置未经验证的通过率。功能发布以第 10 节验收用例为门槛。

建议实施顺序：

1. 确定目标／科目／目录来源契约和覆盖清单，完成首页文字结构与空状态设计。
2. 接通身份、科目与资料处理链路，实现目标确认和首次使用引导。
3. 接通四类学习模块及任务完成事件，实现计划草稿、用户确认和今日任务。
4. 接通复习聚合、恢复位置、统计刷新与异常恢复，完成电脑端和手机查看验收。
5. 在已核验目录覆盖范围内发布 P0，后续按独立需求推进 OCR、移动端完整学习与复杂分析。
