# 个人 RAG 工具：首页与聊天工作区需求

版本：V2.0｜日期：2026-11-14｜状态：用户已确认产品方向，待设计与实现。

本版替代提交 `e00b38c` 中的考研初试工作台需求。旧版的考试目标、科目目录、倒计时、今日学习任务与评分流程不再作为主产品实施依据，历史内容可通过 Git 查阅。

产品范围与竞品取舍见 [产品定位与路线图](product-positioning-and-roadmap.md)。本文的 P0 是目标能力，不表示业务已上线；本次只交付文档，不改代码、接口或数据库。

## 1. 定位与已确认决策

面向大众个人用户，提供以聊天为入口、以自有资料为依据的多功能 RAG 工具。用户创建知识库并导入资料后，可提问、核对出处、生成摘要与提炼要点。

| 事项 | 已确认决策 |
| --- | --- |
| 主入口 | 首页直接进入聊天，在聊天界面切换知识库 |
| 资料组织 | 多个独立、私有的个人知识库，每库可含多份资料 |
| 会话与库 | 同一会话可逐轮切库，会话不绑定唯一知识库 |
| 事实依据 | 每轮只使用当前选定库的资料；其他库历史消息保留可看，不自动成为当前轮事实依据 |
| 回答模式 | 默认仅依据知识库；用户主动开启模型通用知识补充时，区分来源类型 |
| 图片 P0 | 文字 OCR、识别结果预览、原图回看；扫描 PDF 进入文字识别流程 |
| 设备 | 电脑、手机 Web 均支持提问、选库与图片上传；复杂管理电脑优先 |
| 学习 | 下一阶段的独立导航入口，共用 RAG 底座；题目分发、图片作答、判对错和手动更正，不做评分 |

首版不做自动联网搜索、跨库综合回答、企业协作、工作流画布或插件平台。图表语义理解、分块编辑和检索测试等高级能力为后续增强，不作为学习接入的前置条件。

## 2. 首页结构与首次使用

### 2.1 电脑端

```text
左栏                         主区                               资料／来源面板
  新对话                       会话标题与历史消息                    当前库资料
  会话历史                     每轮的库、模式、引用                 上传与处理状态
  知识库管理                   流式回答／摘要                       解析与 OCR 预览
  个人设置                     输入与上传区域                       原始文件／原图
                               当前知识库选择器
                               仅知识库／通用补充开关

下一阶段：左栏增加独立“学习”入口，不改变聊天主入口。
```

知识库选择、模式与上传目标须在发送区域可见。侧面板可以收起，聊天仍可完成；首页不放考试目标、打卡、学习时长或成绩仪表盘。

### 2.2 新用户路径

进入聊天首页 → 在页内创建首个知识库 → 上传资料 → 查看处理状态与预览 → 索引就绪后提问 → 查看回答依据。

- 无库时提供“创建知识库并上传资料”入口，不要求先进入独立管理台，也不假设已有默认库。
- 创建成功后选中该库，继续上传或提问；支持以后新建其他库。
- 无资料或资料未就绪时显示当前原因与下一步，不生成声称来自知识库的回答。
- 创建或选择有效库后，即使库内尚无就绪资料，用户也可主动开启通用知识补充进行一般提问，回答明确标记为模型知识；此行为不代表资料已入库。未选库时先完成页内建库或选库，两种模式都不能绕过此条件发送。

### 2.3 手机端

- 手机可创建首个库、选择现有库、发送问题、选择并上传图片、查看 OCR 和回答引用。
- 会话历史与资料面板采用可展开区域；库选择及回答模式不能藏在用户无法识别的位置。
- 复杂批量管理与高级工具以电脑为主。核心提问和图片上传不能以“请用电脑”代替。
- 长中文库名、文件名与错误信息可展开；页面无整体横向溢出，上传和发送操作适合触控。

## 3. 功能需求

### F01 知识库管理与检索范围

- 用户能创建、查看、重命名和删除自己的知识库，在库内管理多份资料。删除前展示影响并要求确认；不提供跨用户共享或团队协作。
- 当前轮默认检索选定库内所有已就绪、当前可访问的资料，不默认混用其他库，也不自动联网。
- 资料面板展示已就绪、处理中和失败数量。只包含部分可用资料时，说明“本次仅使用已就绪资料”，不暗示全库已处理完成。
- 服务端验证知识库、文件、原图、OCR 文本及引用的所有权与可见性；前端库选择不是授权凭据。
- 当前库被删除或不可访问时清除该选择，提示重新选库；不能静默改用其他库继续发送。

### F02 同一会话逐轮切库

**基本规则**：会话保存连续的可见历史，每轮请求单独确定知识范围。会话标识、当前输入区的选择与每轮已保存范围不是同一个概念。

1. 发送时固定本轮知识库和回答模式；服务端在开始检索时固定可用的资料／索引版本范围，并记录实际引用。不能因后续选择器或索引变化改写本轮范围。
2. 用户消息与回答均能辨认本轮所选库；历史回答的标签和引用不随当前选择器改变。
3. A 库轮次结束后切到 B，A 的消息仍可查看，但 A 的资料、引用、旧回答与包含这些内容的会话摘要不得自动作为 B 轮的事实依据。
4. 用户在 B 轮询问只存在于 A 的资料时，说明当前 B 库资料不足，可提示切回 A；不能直接从旧回答取出 A 的事实。
5. 切回 A 时仍须按当前权限和资料可用状态检查依据，不能把失效引用当作仍可访问的证据。

实现可以保留对话的指令和表达连贯性，但必须满足上述事实隔离结果；不能仅在界面更换标签、实际仍把全部旧库内容交给模型使用。

**生成与切库同时发生**：

- A 轮生成中，选择器可为下一轮改选 B；正在生成的回答继续标记 A，检索与引用仍属于 A。
- 同一会话生成中不能再并发提交下一轮；用户可等待、停止后再发，失败后可重试。
- 重复点击或断线重试不能创建重复轮次或重复完成记录。停止的部分回答标为“已停止”，不冒充已完成答案。
- 切库不清空用户尚未发送的文本，但发送前必须清楚显示它将使用的新库。

### F03 回答模式与资料不足

| 模式 | 行为 | 展示要求 |
| --- | --- | --- |
| 仅知识库（默认） | 以本轮库内证据回答；没有足够依据时说明缺口，可给出已找到的相关片段 | 知识库来源与真实引用；没有依据不制造出处 |
| 知识库＋通用补充 | 用户主动开启后，可在库内依据之外补充模型通用知识；跨库历史仍受 F02 约束 | 区分“资料依据”和“模型通用知识补充”，后者不能伪装为引用 |

- 首次及新会话默认“仅知识库”。用户主动开启的模式在输入区持续可见，直到关闭；每轮保存发送时的实际模式。
- 两种模式均须选择当前可访问的有效库；空库与未选库不同。空库可主动开启模型补充，未选库或库失权时先创建／重新选择，不能用补充模式绕过校验。
- 切库不会悄悄开启通用补充；已主动开启的设置保持可见，当前轮库范围依然明确。
- 通用补充不等于联网检索，也不保证知识实时性。首版不自动访问外部网页获取答案。
- 检索到相关内容不等于证据充分。回答中的资料事实应能由对应引用支持，不能只附上无关命中片段。
- 引用标识须对应实际资料与版本，不能虚构文件、页码或段落。

### F04 资料上传、解析与索引

**首发格式**：PDF（文字型及扫描型）、DOCX、TXT、PNG、JPEG。其他格式不作为 P0 承诺；文件大小、数量和解析容量限制由服务端明确提供并在上传前展示。

- 上传前确定目标库。上传开始后即固定归属；聊天切到另一个库不会移动正在上传的资料。
- 用户能看到“上传中、解析／识别中、索引中、可问答、失败／需处理”等状态；进度不确定时显示阶段，不虚构百分比。
- 只有完成处理且索引可用的内容参与检索。首次处理中的文件不能作为已可用证据。
- 更新已有资料时，新版本完成前仍可使用原先已发布、可访问的版本，并明确提示；新版本成功后切换供后续轮次使用。
- 失败保留明确原因和重试／替换文件入口。一次处理失败不阻断其他已就绪资料的问答。
- 删除资料后不再进入新检索；历史引用显示来源不可用，不能继续通过缓存原文或旧索引片段绕过访问检查。

### F05 图片 OCR、预览与原图

- P0 以清晰印刷文字、书页／截图及扫描 PDF 的文字提取作为主要验收对象。保留原图或原文件，并将识别文本关联到对应图片／页。
- 支持识别文本预览与原图对照回看；不要求普通用户逐块配置索引或逐页手工确认后才能使用。
- 无法提取有效文字或处理失败时，显示需处理状态，不把空白识别结果标为可回答。可能不完整时提供提示与预览，用户可重传更清晰资料或改用文本文件。
- 已索引 OCR 内容若需替换，应产生可追踪的新版本并重新索引；不能只改变预览文本而继续检索旧内容。P0 不要求内置分块编辑器。
- 图片中的标题、数字被识别，不代表已理解统计图、流程图、公式推导或示意图。首版界面明确“按识别文字检索”，不能承诺完整视觉理解。
- 学习图片作答是下一阶段的独立输入与判断流程，不能把 OCR 成功当作判题正确的证明。

### F06 引用与来源回看

- 回答旁展示真实使用的资料名称、知识库、来源版本或更新时间，以及支撑片段；历史引用使用对应轮次的范围。
- 点击可打开有权限的原始文件／图片与相应提取文本。解析具备可信定位信息时可定位到页、章节或段落；缺少精确定位时如实回退到文件与片段，不伪造坐标。
- PDF 页码、DOCX 章节／段落和单张图片采用各自有效定位方式，不强行给所有格式套用页码。
- 多段资料支持同一结论时可分别展示引用；通用知识补充单独标记，不附假的库内引用。
- 源资料删除或权限变化后，引用显示不可用；原文和片段读取重新校验权限。会话中其他库的轮次仍可按其自身权限查看。

### F07 摘要与信息提炼

- 从聊天或资料面板发起，对当前库的一份或多份指定资料请求摘要、要点或信息提炼；不自动扩展到其他库。
- 发起前明确请求范围，结果说明实际覆盖的资料与内容范围，并能回看依据。
- 仅使用检索片段时标为“基于本次检索片段的提炼”；不能把 top-k 片段摘要表述为完整阅读了整库或全文。
- 全文／全部所选资料摘要若超出可处理范围或部分资料未就绪，应提示缩小范围或分批处理，不悄悄省略后宣称全部完成。
- 结果作为本轮会话内容保存，可复制文本。首版不另外建设学习笔记体系或复杂内容导出平台。

### F08 会话历史与重访

- 用户可新建会话、查看自己的历史并继续提问。同一会话可能包含多个库的轮次，不能强制用单个库代表整段历史。
- 历史保留各轮的库、回答模式、引用与完成／失败／停止状态；重访不把所有旧消息重新标成当前选择器的库。
- 继续发送时清楚显示下一轮所用库和模式；无有效库时要求重新选择，不能沿用已失效标识。
- 历史消息可读性与事实依据权限分别处理；已不可用的资料不能因出现在历史或摘要中而重新进入问答依据。
- 退出登录、会话过期或切换账号时，清理前一账号的私人缓存，不短暂展示其他人的库、原图或聊天记录。

## 4. 状态与恢复规则

| 状态 | 页面行为 |
| --- | --- |
| 无库 | 页内创建或选择有效库后才可发送；保留输入并说明模式，建库后可上传或主动开启通用补充 |
| 库为空或仅有处理中资料 | 提示上传／等待；当前库无可用资料的事实与处理状态可见 |
| 库内只有部分就绪 | 可用部分正常检索，展示范围限制与剩余处理状态 |
| OCR／解析／索引失败 | 说明失败阶段，可重试或替换文件，不影响其他就绪资料 |
| 资料不足 | 说明当前库无法充分回答，可查看相关依据、补资料或主动切换模式 |
| 模型／网络失败 | 保留输入和已提交轮次状态；重试不重复创建，部分输出不标为完整成功 |
| 生成中切库 | 当前回答范围固定，新选择只影响下一轮 |
| 库删除或不可访问 | 清除失效选择，阻止按其发送；不自动切另一个库 |
| 原始引用不可用 | 显示失效状态，禁止返回已失权原文或片段 |
| 局部面板加载失败 | 独立错误和重试；不清空其他有效内容，也不把未知数量显示为 0 |
| 身份失效／切换 | 转入认证或重新加载个人数据，清理上个身份的缓存 |

## 5. 学习模块边界

下一阶段在左侧加入独立“学习”入口，调用同一知识库、解析、检索与引用能力，不改变默认聊天首页。

已确认：题目分发、图片作答、自动判对／错，用户可以自己判对／判错或更正；不设计分数、满分、部分得分或评分排名。

学习专题另行确定：原题抽取与 AI 生成的使用范围、标准／参考答案来源、手写答案识别、无法识别或无法可靠判断时的处理、人工结果覆盖与追溯规则。最终对错结果与“处理中／待人工”等流程状态需要分别定义，不能因为最终结果二元就强行猜一个结果。

P0 不显示可点击但无功能的学习入口，也不要求学习模块上线后才发布通用 RAG。考试规划、院校科目匹配、倒计时与今日学习任务不再是首页核心或默认实施事项。

## 6. 交互与数据契约要求

下列描述待实现能力，不声明已有接口路径，也不在本文决定表名或迁移方式：

| 契约 | 必需内容与边界 |
| --- | --- |
| 知识库 | 所有权、名称、可访问状态、资料及就绪情况；请求始终校验个人隔离 |
| 导入任务 | 固定目标库、文件和版本、处理阶段、可用结果或失败原因；大小／数量能力限制 |
| OCR 与预览 | 原始文件／页、对应识别文本、可用与异常状态、受权限控制的回看信息 |
| 每轮请求 | 会话、选定库、回答模式、去重标识；服务端确定实际可用的资料／索引范围 |
| 每轮响应 | 固定范围、回答内容、模式、引用、来源类型、生成／完成／失败／停止状态 |
| 历史与恢复 | 各轮原始范围和引用、下一轮可用库；不可通过全会话摘要混入旧库事实 |
| 摘要 | 请求范围、实际覆盖范围、处理状态、结果与对应资料依据 |

服务端是范围、权限、版本、引用和完成状态的权威。输入区的当前库不能回写历史，前端声明“使用 B 库”不能替代真正的检索与历史上下文隔离。知识库内容作为资料处理，不作为可以改变系统权限或检索范围的指令。

## 7. 现有基础与实现缺口

截至本文编写，[前端入口](../../frontend/src/main.tsx) 是首页为空的 React/Vite 路由壳；[后端 v1 路由](../../backend/src/study_platform/api/v1/__init__.py) 仍是预留路由，已接通的业务以外能力是健康检查。数据库与框架基础已建立，不代表通用 RAG、OCR 或学习模块已实现。

可复用候选包括用户隔离、资料／索引版本、分块、向量、消息引用、异步任务与运行持久化。以下需先完成技术设计：

- 当前容器是 `courses`，资料和会话强绑定课程；新契约需要独立知识库语义，不能只替换页面上的“课程”文案。
- 原会话单个 `course_id`／会话级范围不能直接表达同一会话逐轮换库；需要逐轮保存范围、引用和回答模式，并调整上下文与会话摘要策略。
- 图片资料的 OCR、预览、对象访问及手机上传需要完整接口与解析链路；图片作答另有下一阶段契约。
- 当前学习表与接口草案含 `score`、`max_score`、`total_score` 等评分语义，且缺少明确的人工改判契约；不能直接作为新学习产品要求。
- 先制定适配与迁移方案，再更改模型、约束与接口；本次不删除表、迁移数据或接管框架内部表。

既有 [架构](../architecture/01_Architecture_Design.md)、[数据库](../architecture/02_Database_Design.md)、[API](../architecture/03_API_Design.md) 是遗留设计快照；新产品方向以本文件及[产品定位](product-positioning-and-roadmap.md)为准。既有[数据库规则](../database-rules.md)中的技术约束需在后续设计中逐项审查兼容性。

## 8. 验收场景

验收使用可运行的业务链路和明确的测试资料；演示或模拟数据须标注，不作为已上线事实。

| 编号 | 场景 | 通过标准 |
| --- | --- | --- |
| R01 | 新用户无库进入首页 | 首页为聊天，能页内建库和上传，不强制跳管理台，不声称已有资料 |
| R02 | 同用户多库、不同用户私有库 | 可管理多个库；另一账号不能查询其文件、OCR、原图或引用 |
| R03 | 同一会话 A → B | 历史保留，每轮显示原库；B 轮实际检索与事实依据不混入 A |
| R04 | A 含唯一事实，B 没有；B 轮追问该事实 | 仅知识库模式明确依据不足，不能从 A 旧回答或会话摘要偷带事实 |
| R05 | B → A 再提问 | 按 A 的当前权限和可用资料作答；不沿用失效引用 |
| R06 | A 回答生成中选择 B | A 的标签、引用和范围不变；B 只影响下一轮，同会话不并发发送 |
| R07 | 默认与主动开启通用补充 | 默认严格库内；主动开启后内容来源分开，没有伪造引用或自动联网 |
| R08 | A 开始上传后聊天切到 B | 文件仍归 A，处理状态清楚标明目标库，不误入 B |
| R09 | 新文件处理中／新版本替换失败 | 未就绪新内容不检索；有旧可用版本时明确使用旧版，不假装更新成功 |
| R10 | 新索引在回答过程中发布 | 本轮引用仍指向实际使用版本，下一轮可使用新版本，旧消息不被改写 |
| R11 | PNG／JPEG 和扫描 PDF | 可看 OCR 结果及对应原图／原页，索引就绪后能检索其文字 |
| R12 | 空白、模糊或 OCR 失败资料 | 状态如实，无法提取有效文字时不标可问答，可替换或重试，不声称准确识别全部内容 |
| R13 | 图片只有图表、流程或示意信息 | 明确按识别文字处理，不把少量文字当作完整图像语义结论 |
| R14 | 相关内容存在但不足以支持问题 | 明确回答边界，引用真实相关片段，不编造资料或确定事实 |
| R15 | PDF、DOCX、图片引用回看 | 打开有效源与对应文本；可信定位可用则定位，否则如实回退，无假页码 |
| R16 | 资料删除或访问失效 | 新轮次不使用失效内容，引用不可绕权限读取；其他有效内容仍可用 |
| R17 | 重复发送、断线重试和停止生成 | 不产生重复轮次；失败／停止状态正确，部分回答不标完成 |
| R18 | 摘要请求与实际覆盖不一致 | 清楚显示实际范围；片段提炼不冒充全文，超限或未就绪时提示缩小／分批 |
| R19 | 重新登录或重访多库会话 | 各轮库、模式、引用仍正确；下一轮范围可见，未把全会话绑定到最后一个库 |
| R20 | 当前库被删除 | 清除失效选择并要求重新选库，不静默使用其他库 |
| R21 | 手机核心操作 | 可建库、选库、提问、上传图片、查看 OCR 及引用，不以电脑入口替代 |
| R22 | 长名称、键盘与触控 | 范围和模式始终可辨，状态不只靠颜色，核心按钮可达，无整页横向溢出 |
| R23 | 模块加载失败、会话过期、账号切换 | 局部恢复且未知不显示为 0；私人缓存不跨账号残留 |
| R24 | P0 页面入口 | 无学习占位死链，无考试规划默认入口；所有正式操作有目标页面与恢复路径 |
| R25 | 无库与有库但无就绪资料时开启通用补充 | 无库不能绕过选库发送；空的有效库可主动补充，明确无库内依据且不产生假引用 |

## 9. 文案、指标与发布门槛

- 使用“知识库、资料、来源、识别文本、当前范围、模型通用知识补充”等中文术语，保留原始文件名；用户无需理解 LangChain／LangGraph 或向量参数。
- 等待、缺资料、处理失败与权限错误给出不同说明；不能用统一空白页掩盖真实状态。
- 首版关注导入后可问答成功情况、首页问答启动、引用打开成功、切库范围正确性、OCR 异常恢复及摘要覆盖表达。评价质量时记录测试资料与模型配置，不把一次演示视为准确率承诺。
- P0 发布需完成本章及第 8 节场景，并在真实资料、手机和电脑上验证；尚未实现的契约、模型服务和解析能力属于上线依赖，不得以静态页面替代完成。
- 高级分块编辑、检索测试、图表理解及独立学习模块分别排期；其详细专题不得重新把主首页变成学习任务工作台。
